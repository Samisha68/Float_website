## What Float gives you

<CardGroup cols={3}>
  <Card title="Credit lines" icon="fa-solid fa-file-invoice-dollar" href="/overview#the-journey">
    Submit a credit-line request, get back a risk band, confidence and reason codes, and a credit facility with a limit.
  </Card>
  <Card title="Verified repayment" icon="fa-solid fa-link" href="/proof-of-concept">
    Repayment is auto-deducted through a delegation the business signs. Float verifies it on-chain.
  </Card>
  <Card title="Float Score" icon="fa-solid fa-shield-halved" href="/architecture#provider-reported-state-vs-float-verified-evidence">
    Portable, consent-gated, built only from evidence Float verifies. The score output is still being built.
  </Card>
</CardGroup>

<Warning>
Funds move only through the capped, revocable delegation the business signs. The business can revoke it at any time. Float manages limits, repayment tracking and verification.
</Warning>

## Explore by product

<Tabs>
  <Tab title="Credit lines">
    Credit lines use `kind: credit_line` on the underwriting endpoint. The credit-line flow is still a proof of concept. See [Proof of concept](/proof-of-concept).

    | Step | Call | You get |
    |---|---|---|
    | 1 | `POST /v1/businesses` | `biz_…`, created or linked |
    | 2 | `POST /v1/underwriting_requests` | `uwr_…` with status `pending` |
    | 3 | `GET /v1/underwriting_requests/{id}` | An assessment once `completed` |

    <Tip>There is no approve/decline field and no price in an assessment. The decision to offer credit is the provider's.</Tip>
  </Tab>
  <Tab title="Float Score">
    The Float Score is a **read** over Float-verified outcomes. It never includes amounts, providers or invoices.

    <CardGroup cols={2}>
      <Card title="Consent first" icon="fa-solid fa-user-check">
        Record it with `PUT /v1/businesses/{id}/consent`. Without it, reads return `403`.
      </Card>
      <Card title="Verified only" icon="fa-solid fa-circle-check">
        Provider reports never count. Only chain observations Float makes itself.
      </Card>
    </CardGroup>

    <Note>The reputation `band` is `null` today. The score output is still being built.</Note>
  </Tab>
  <Tab title="Invoices (later)">

## Quickstart

<Steps>
  <Step title="Grab a test key">
    Test keys start with `fk_test_` and only ever touch test data. There is no self-serve signup yet, so see [Environments and access](/overview#environments-and-access) for how to get one.

    ```bash
    export FLOAT_API_KEY=fk_test_…
    ```
  </Step>
  <Step title="Create a business">
    <CodeBlocks>
    ```bash cURL
    curl -X POST https://api.float.xyz/v1/businesses \
      -H "Authorization: Bearer $FLOAT_API_KEY" \
      -H "Content-Type: application/json" \
      -H "Idempotency-Key: $(uuidgen)" \
      -d '{"external_id":"acct_8842","display_name":"Lagos Freight Ltd","country":"NG"}'
    ```

    ```typescript TypeScript
    const res = await fetch("https://api.float.xyz/v1/businesses", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.FLOAT_API_KEY}`,
        "Content-Type": "application/json",
        "Idempotency-Key": crypto.randomUUID(),
      },
      body: JSON.stringify({ external_id: "acct_8842", display_name: "Lagos Freight Ltd", country: "NG" }),
    });
    const { data: business } = await res.json(); // business.id → "biz_01J…"
    ```

    ```python Python
    import os, uuid, requests

    res = requests.post(
        "https://api.float.xyz/v1/businesses",
        headers={
            "Authorization": f"Bearer {os.environ['FLOAT_API_KEY']}",
            "Idempotency-Key": str(uuid.uuid4()),
        },
        json={"external_id": "acct_8842", "display_name": "Lagos Freight Ltd", "country": "NG"},
    )
    business = res.json()["data"]  # business["id"] → "biz_01J…"
    ```
    </CodeBlocks>
  </Step>
  <Step title="Request a credit line">
    Underwriting is asynchronous: you get `202` and status `pending`.

    {/* TODO: the credit_line request payload is not documented anywhere yet. This keeps the existing request structure (business + kind) and omits any credit-line fields. Replace with the real payload once it is agreed. */}

    ```bash
    curl -X POST https://api.float.xyz/v1/underwriting_requests \
      -H "Authorization: Bearer $FLOAT_API_KEY" \
      -H "Content-Type: application/json" \
      -H "Idempotency-Key: $(uuidgen)" \
      -d '{
        "business": "biz_01J…",
        "kind": "credit_line"
      }'
    ```
  </Step>
  <Step title="Read the assessment">
    Poll `GET /v1/underwriting_requests/{id}`, or follow `GET /v1/events`. A completed request embeds the assessment. The band feeds the Float Score, which is still being built.

    {/* TODO: this assessment example is the documented invoice shape, trimmed. The credit_line assessment fields are not documented yet. */}

    ```json
    "assessment": {
      "band": { "key": "moderate_risk", "label": "Moderate risk", "ordinal": 2, "of": 3 },
      "confidence": { "level": "medium" },
      "reasons": [{ "code": "DEBTOR_PAYMENT_HISTORY_LIMITED", "direction": "negative" }]
    }
    ```
  </Step>
</Steps>

## Sandbox

With a `fk_test_` key, underwriting is a sandbox that returns mock results. Sandbox assessments carry `engine.name: "float-sandbox"` and a `SANDBOX_RESULT` reason. They are not real assessments.

{/* TODO: the outcome suffixes below are documented for invoice numbers only. Confirm how, or whether, they apply to credit-line requests. */}

For invoices, an invoice-number suffix picks the outcome. Try `INV-0091-SBX-REJECT`.

| Suffix | Outcome |
|---|---|
| *(none)* | `completed`, band `moderate_risk` |
| `-SBX-BAND-<key>` | `completed` with that band (`low_risk`, `high_risk`, …) |
| `-SBX-REJECT` | `rejected` |
| `-SBX-INFO` | `requires_information`; any information push completes it |
| `-SBX-FAIL` | `failed` |
| `-SBX-SILENT` | stays `processing` until the SLA timeout |
| `-SBX-UNAVAILABLE` | retried, then `failed` / `underwriting_dispatch_failed` |
